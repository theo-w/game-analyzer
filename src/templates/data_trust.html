真实竞品 ↔ 看板：数据怎么流动

  1. 抓取：分析向导 /guide 选择 Steam / TapTap / Google Play，拉取公开评论。
  2. 写入：结果保存到 data/mvp/users/{用户名}/steam_dataset.json（评论 + 样本指标），按登录用户隔离。
  3. 看板读取：运营看板 /dashboard 通过 API 读同一份数据，抓取后自动同步，无需单独导入。
  4. 筛选查看：在看板选择产品、数据来源、周期，点击「应用筛选」展示 KPI 与排行。

页面分工（数据同源）：向导侧重深度报告与行动建议；看板侧重筛选汇总与预警；竞品工作台侧重横向对比。不是三套独立数据库。

指标数据来源

Steam / TapTap / Google Play 评论与评分 真数据 公开评论抓取；看板与竞品页会标注来源。
Owner DAU / 收入 / 内购 需导入 通过「导入指标」上传 CSV，不与公开商店自动打通。
用户路径 / 转化漏斗 / 实时曲线 已移除 这类分析依赖客户端埋点（Firebase、Adjust 等）或内部经营数据，商店公开评论无法支撑， 演示占位数据已随功能一并下线。导入经营指标后，报告与 KPI 会使用您自己的数据。
平台同步 API（无密钥时） 模拟 配置密钥后切换为真实拉取。
  • 公网 Demo / 开发环境：模拟支付，扫码后点「支付完成」即可演示升级，无真实扣款。
  • 生产试点：通用回调 POST /api/payment/webhook（HMAC）；或 Stripe Checkout POST /api/payment/webhook/stripe（沙箱卡号 4242…）。
  • API 配额：按套餐月度计数；管理员与坐席账号不限。

试点上线检查（技术）

  • 设置 SECRET_KEY、APP_ENV=production
  • 关闭 ALLOW_DEMO_ACCOUNTS（正式客户环境）
  • 关闭 PAYMENT_TEST_MODE 并配置 PAYMENT_WEBHOOK_SECRET
  • 持久化 data/ 卷（SQLite）或迁移 Postgres
